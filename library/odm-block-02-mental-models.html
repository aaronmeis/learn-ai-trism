Block 2: Mental models

Block 2 study note: pillars versus layers, standards anchoring, and runtime versus architecture.

Time: 45 minutes Goal: Hold three models you can draw in a review: pillars beside layers, standards as the anchor, runtime inspection beside identity and privilege. Pack: AI-TRISM hub

Business Explanation

Business Explanation

A design review fails when the architect picks a vendor diagram and calls it the requirement. These three models tell you which picture is a placement aid, which document can be certified, and which controls still matter after a guardrail misses.

Model 1. Pillars beside layers

Pillars answer "which concern is this?" Layers answer "where does the control run?"

Pillars [S9] [S10] Layers [S9], count from [S1]
Shape Explainability, ModelOps, application security, privacy Governance, runtime inspection and enforcement, information governance, infrastructure and stack
Use Crosswalk to the intake boundaries Place a component
Source grade Secondary. E1A partial Names secondary. Count primary. E1B partial
Risk Looks like a complete trust model. Fairness and safety are not named. Debate 4 open Sounds like Gartner's own diagram. The free Gartner page does not draw it

IBM does not use either list as a neat set of four. It speaks of governance, data protection and classification, and runtime inspection [S8]. Hold that third cut so a single vendor page cannot settle Debate 1.

The pack prefers layers for architecture because they name enforcement points. CLAIMS-AND-DEBATES calls that preference the architect's convenience, not a finding. E1W ran: the free press release uses "four layers" and does not publish pillars. That weakens the claim that Gartner names pillars on free pages. It does not erase the secondary pillar list.

Draw this once:

Concern (pillar, secondary) Place (layer, names secondary)
explainability governance: who owns the explanation standard
ModelOps governance + build records for release
application security runtime inspection + infrastructure identity
privacy information governance

A control can sit in one layer and serve two pillars. Least privilege on an agent is infrastructure, and it serves application security and privacy.

Model 2. Anchor the design to standards

Debate 2 asks whether you design against TRiSM or against auditable standards.

Side Claim Desk result
A TRiSM is enough to design against, because it organizes the lifecycle [S8] [S9] E2A ran. No published design-review architecture in the search used TRiSM as the sole auditable anchor. Claim A stays weak.
B Anchor to NIST AI RMF and ISO/IEC 42001. Use TRiSM as a capability checklist [S2] [S4] [S5] E2B ran. ISO/IEC 42001 is certifiable through independent bodies. ISO does not itself certify [S14] [S15].

E2W softens one word in Claim B. "Auditable" fits ISO better than NIST. AI RMF and AI 600-1 state voluntary use. No NIST certification path showed up [S2] [S3].

Working rule for this pack:

  1. Requirements and evidence go to the AIMS, ISO/IEC 42001.
  2. Risk language goes to Govern, Map, Measure, Manage [S2].
  3. GenAI-specific actions wait on AI 600-1 tables you have not finished [S3].
  4. TRiSM layers tell you where a tool category sits.
  5. The crosswalk is how a control id in one document points at a control id in the other [S4].

The TDD conceptual view already splits the work this way. Capabilities C1 to C4 track IBM's account. C8 is compliance mapping and evidence, tied to NIST, ISO, and law. Use C8 as the slot for the anchor. Do not rename C8 to "TRiSM certification." Nothing in the ledger gives TRiSM a certification path.

Model 3. Runtime inspection beside architecture

Debate 3 is about weight, not about whether filters exist. Both sides keep an inspection point.

Claim A, from Bo Li's talk: if the model cannot be fundamentally fixed, put an outer AI firewall or guard rail around it. Start with red teaming. Risk assessment cannot be skipped [S11].

Claim B, from the CSA keynote: filters and rules cannot cover an infinite input and output space. Ask who the agent is and what it can access. Over-permissioning is the failure mode. The speaker works for a vendor that sells behavioral detection. Keep that interest visible [S12].

E3A counted the seven LLM01:2025 mitigations [S7b]:

# Mitigation Bucket
1 Constrain model behavior in the system prompt Process and prompt design
2 Define and validate expected output formats Filtering and inspection
3 Input and output filtering Filtering and inspection
4 Privilege control and least privilege Privilege and architecture
5 Human approval for high-risk actions Process
6 Segregate and identify external content Architecture and process
7 Adversarial testing. Treat the model as an untrusted user Process

About two items are filtering. About five are privilege, architecture, or process. That supports more weight on architecture. It leaves the runtime layer in place, because items 2 and 3 are real controls, and Bo Li still wants the outer layer when the model stays broken.

The TDD logical view copies this split on purpose. The runtime gateway is the choke point for prompts, outputs, and tool calls. The agent identity broker is a separate component so a gateway failure does not become full privilege. Policy sits outside the model. Retrieval content is untrusted. Those component boundaries are a proposal. Gartner did not publish them.

E3W, a lab comparison of a guardrail product against least privilege, is unrun. Do not quote detection rates.

What you leave open

Debate 4. A first mapping in the claims note sends valid and reliable toward ModelOps, secure and resilient toward application security, explainable and interpretable toward explainability, and privacy-enhanced toward privacy. Safe, and fair with harmful bias managed, have no pillar with those names. That mapping is labeled agent inference. E4A and E4B are partial. E4W is unrun. Say the gap. Do not close it.

Actions

  2. 15 minutes. Write five numbered lines for Model 2 in your own words. Include the E2W softening so you do not call NIST a certificate.

  4. 10 minutes. Write one sentence you will say if a reviewer calls the layer preference "what Gartner proved."

Retrieval check

Why does this pack place tools on layers and keep pillars as a crosswalk?
Answer

Layers name enforcement points, which is what a reference architecture has to draw. Pillars name concerns from secondary sources. The preference is recorded as convenience in Debate 1. The Gartner press release confirms the count of layers and does not confirm either set of names [S1] [S9].

What is the design anchored to after Debate 2?
Answer

ISO/IEC 42001 for the AIMS and conformance, NIST AI RMF for Govern, Map, Measure, and Manage. TRiSM stays the capability and tool map. NIST is voluntary, so "auditable" is the ISO side of the pair [S2] [S14] [S15].

What order does Debate 3 support?
Answer

Red team and risk assessment first [S11]. Outer inspection for prompts, outputs, and tool calls. Privilege, human approval, segregated external content, and a separate agent identity so the gateway is not the only control [S7b] [S12].

Exit criteria

  • Debate 4 is marked open.
  • You can sort the seven LLM01 mitigations from memory.
  • You can say E3W is unrun, so there is no detection-rate claim.
