NotebookLM Prompt Set — AI-TRISM

Alias: tdd-ai-trism · Date: 2026-11-09

Grounded in pack RESOURCES, source ledger, Elicit light research, and staged videos.

Tailored prompts (4)

T1

Using only the sources, write the CONCEPTUAL architecture view of AI TRiSM (AI Trust, Risk and Security Management). Cover the problem it solves, the actors and their goals, the capabilities it provides, and the key concepts and how they relate. Then state how each source structures AI TRiSM: some describe four pillars and some describe four layers. Attribute each structure to the source that gives it, say whether that source is a vendor or an independent body, and do not merge the two structures. Do not name products, SKUs or regions; this is the capability altitude. End with a table mapping each capability to the source that supports it. Mark where the sources are silent.

T2

Using only the sources, write the LOGICAL architecture view of AI TRiSM. List the logical components needed to realize its controls across the AI lifecycle, such as an AI inventory, data mapping, policy decision, evaluation and red teaming, runtime inspection, agent identity, monitoring, explainability, model release, and evidence storage. For each, give responsibilities, inputs and outputs, and say which source supports it. List the logical data entities with key attributes and relationships. Describe the main flows, including the path of a user or agent request at runtime, with trigger, payload, and sync or async. Stay vendor-neutral. Mark every component or flow that the sources do not support instead of inventing it.

T3

Using only the sources, describe how AI TRiSM controls are realized and deployed in practice. Cover where enforcement points sit (inline proxy, API gateway, agent, sidecar, release pipeline), what data stores hold logs and evidence, and which named products, services or open-source tools the sources give as examples. For each named example, state which source names it and whether that source is vendor-authored. Do not infer availability in government, GCC, GCC High or DoD environments; list only what the sources state about government or regulated environments, and otherwise say they are silent. Do not state licensing tiers unless a source does. Mark silence.

T4

Using only the sources, describe the AI elements and integration surface of AI TRiSM. For LLM applications, retrieval-augmented generation, AI agents, and classical machine learning models, say what each reads and writes, the data path from training data and prompts to outputs and monitoring, and the controls the sources attach at each point. Map the OWASP Top 10 for LLM Applications 2025 risks named in the sources to those controls and say which have no stated mitigation in the sources. Then list the integration surface the sources mention: identity for agents, SIEM and incident tooling, data catalog and data loss prevention, model registries, and third-party model providers. Mark silence.

Room-craft decision packet (T5 / Create Your Own)

Paste into Studio → Report → Create Your Own, or let the W8 PS1 create report_room_craft. Full note: notebooklm-room-craft-decision-packet.

Using only the sources, produce an Executive Decision Packet report for AI-TRISM. This is a decision artifact for a high-stakes room, not a study essay and not a stack tour. Ground every claim in the sources. Prefer primary docs and named lectures when present. Mark silence explicitly. Do not invent numbers, benchmarks, dates, or case examples.

Hard rules - Lead with the answer. No warm-up, agenda, or project history before the recommendation. - If a fact is unknown, do not guess. Write: UNKNOWN — will be known by [date or milestone] via [owner/method]. Guessing destroys trust. - Keep supporting reasons to three or fewer. Remove nondiagnostic detail rather than labeling it "FYI." - Express value in the room's units: cash, risk, customers, or time. - Separate Run (keep the lights on) from Change (strategic investment) if both appear; do not blend them into one story.

Required report structure (use these exact section headings)

1. First 60 seconds (spoken script)

Write a spoken opening the presenter can deliver in under 60 seconds. It must include, in order: 1. The recommendation / Ask (one breath). 2. Business impact or dated cost of no. 3. The decision needed today.

Also include a one-line Stakes Sentence in this form: If we do nothing, [Value at Risk] by [Date]. If we act, [Outcome] by [Date] at [Cost/Risk]. If sources lack a concrete number or date, keep the slots visible and mark UNKNOWN with a known-by date. Do not fill gaps with plausible fiction.

2. Five-slide spine (titles + contextual reference)

Produce exactly five live-room slides. For each slide provide: - Action title (full sentence conclusion, not a topic label). Titles alone must pass the Titles Test: reading only the five titles must carry the argument. - One-sentence job of the slide (what the room should conclude). - Body content outline (bullets only; max three reasons or proof points). - Written So-what line that must appear on the exhibit. - Source anchor or silence note.

Use this contextual map unless the sources mandate a clearer MECE order for AI-TRISM: 1. Ask + outcome — what to approve/decide and the enterprise result. 2. Why now / stakes — complication, urgency, dated cost of delay. 3. The change or options — what changes, or the option set with the recommended path. 4. Value proof — diagnostic evidence the investment or decision pays (BVS); include one human-value beat only if sources support a named person + number. 5. Decision today — cost, time, capacity stopped, residual risk, and the explicit ask / next 90 days.

Note the 5+20 rule in one line after the five slides: five slides in the room; deeper evidence stays in appendix (list appendix topics only; do not write the appendix).

3. Five killer questions (20-second answers)

For each question write a 20-second spoken answer, then a one-line elevate (strategic implication). If unknown, use the UNKNOWN — known-by pattern. Do not skip any question.

  1. Why now?
  2. What if we wait? (dated cost of no)
  3. Who else has done this? (benchmark or analogue from sources only)
  4. What are we stopping? (capacity / tradeoff)
  5. What if this slips? (risk and recovery)

4. Uncertainty register

Table with columns: Gap, Why it matters to the decision, What will be known, By when, Owner or method. Include every UNKNOWN from sections 1–3. If nothing is unknown, write "None — all decision-critical facts are sourced" and list the strongest source anchors.

5. Readiness falsifiers

Answer yes/no with evidence or silence: - Can the Ask be stated in one breath? - Is value named in cash, risk, customers, or time with a date? - Would a CEO leaving at minute five still know the Ask and the cost of no? - Do the five titles alone tell the story? - Are Run and Change kept separate where relevant?

6. Silence and out of scope

List what the sources do not cover that a real room might still ask. Do not fill those gaps.

Standard Briefing Document (verbatim)

Create a comprehensive briefing document that synthesizes the main themes and ideas from the sources. Start with a concise Executive Summary that presents the most critical takeaways upfront. The body of the document must provide a detailed and thorough examination of the main themes, evidence, and conclusions found in the sources. This analysis should be structured logically with headings and bullet points to ensure clarity. The tone must be objective and incisive.

Standard Study Guide (verbatim)

You are a highly capable research assistant and tutor. Create a detailed study guide designed to review understanding of the sources. Create a quiz with ten short-answer questions (2-3 sentences each) and include a separate answer key. Suggest five essay format questions, but do not supply answers. Also conclude with a comprehensive glossary of key terms with definitions.

Data table description

Columns: Claim, Layer or component, Practice implication, Source support (strong/medium/thin), Silence notes. One row per major claim about AI-TRISM.

Extra deep-dive prompts — AI-TRISM

Injected into the W8 runner as additional Create Your Own reports. Paste manually into Studio → Report → Create Your Own if running by hand.

report_third_party

Using only the sources, catalog every THIRD-PARTY and EXTERNAL system that AI-TRISM integrates with. Include non-vendor clouds and SaaS data sources, SIEM and SOAR, ITSM and ticketing, on-premises file shares and databases, endpoints, identity providers, and complementary or competing governance and privacy tools. For each: vendor, direction (in, out, or both), mechanism (native connector, API, agent, SIEM feed, export), data exchanged, authentication, known limits, and government-cloud support. Present it as a table, then list integrations the sources mention but do not document. Mark silence.

report_failure_modes

Using only the sources, catalog failure modes and security weaknesses in AI-TRISM deployments. For each: symptom, root cause, which view it belongs to (conceptual, logical, physical, integration), blast radius, and the mitigation the sources support. Include misconfiguration, licensing gaps, integration breakage, and AI-specific risks such as oversharing through grounding. Mark silence.

report_framework_crosswalk

Using only the sources, build a crosswalk for AI-TRISM that places its elements into TOGAF ADM phases (A Vision, B Business, C Data and Application, D Technology), into DoDAF viewpoints (OV-1, OV-2, OV-5b, SV-1, SV-2, SV-4, SV-6, DIV-1/2/3, StdV-1), and into UAF 1.3 grid cells (domain-aspect pairs such as Sm-Ov, St-Tx, Op-Sr, Op-Cn, Sv-Sr, Rs-Sr, Sc-Sr, Sd-Tx, Pj-Rm, Ar-Sr), and shows which elements are conceptual, logical, or physical. Prefer UAF 1.3 labels from the OMG grid. Keep DoDAF in the table alongside UAF. Where the sources do not support a placement, say so rather than inferring. Do not merge this architecture-framework crosswalk with the NIST-to-ISO 42001 control crosswalk.

NotebookLM debate prompts — AI-TRISM

Created 2026-11-09. These are not injected by w8-prepare: the runner builds its extra reports from code, not from this file. Run them by hand in Studio, Report, Create Your Own, or with nlm report create after the W8 runner has finished (pattern in scripts/OPERATOR-COMMANDS.md, room-craft section). One prompt per debate in CLAIMS-AND-DEBATES.

Why separate: the debates test NotebookLM's sources against the claims note. A report that only restates sources would not do that. Ask for both sides and for silence.

Rules for every prompt: use only the notebook sources, attribute every point to a named source, say whether that source is vendor-authored, an independent body, a law, or a talk, and list what the sources do not say. Do not resolve a conflict between sources; show it.

D1 Pillars or layers

Using only the sources, answer: how is AI TRiSM structured? Report what each source says about four pillars (explainability and model monitoring, ModelOps, AI application security, privacy) and about four layers (AI governance, runtime inspection and enforcement, information governance, infrastructure and stack). Say which source gives which and whether it cites a Gartner document it can be traced to. State whether any source treats the two as the same thing at different levels. Do not choose between them. List what a reader would need from Gartner itself to settle it.

D2 Design against AI TRiSM or against standards

Using only the sources, compare AI TRiSM, NIST AI RMF, ISO/IEC 42001 and the EU AI Act as things an architect can design against. For each, say what kind of thing it is (market category, voluntary framework, management-system standard, law), whether the sources describe a way to assess conformance, and what the NIST to ISO/IEC 42001 crosswalk maps. Show where sources disagree or are silent, including whether AI TRiSM has any certification.

D3 Are runtime guardrails enough

Using only the sources, report the case that a runtime inspection or guardrail layer is the practical control point for AI application security, and the case that guardrails are necessary but insufficient. For each side, give the evidence the sources offer, say whether the speaker or author sells a product that benefits from that view, and list any measured results versus assertions. Report which mitigations for prompt injection the sources list that are filters and which are privilege limits, identity or human approval. Do not resolve the dispute.

D4 Do the pillars cover NIST's trustworthiness characteristics

Using only the sources, list NIST's seven trustworthiness characteristics and the AI TRiSM pillars or layers. For each characteristic, say which pillar or layer the sources connect it to, and flag any characteristic, such as fair with harmful bias managed or safe, that no source connects to a pillar or layer. Separate what the sources state from what is your inference, and label inferences as such.
