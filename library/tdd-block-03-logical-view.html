Block 3: Logical view

Block 3 study guide: logical components, entities, and the untrusted runtime path.

Time: 60 minutes

Business Explanation

Business Explanation

Capabilities do not stop an incident. Parts with responsibilities do. This hour shows the proposed parts, the records they share, and the one path a user request takes. Two links on that path carry content the organization did not write. Those links are drawn in red so a later design review cannot treat retrieved text as trusted company data.

Goal

Give every capability C1 to C8 at least one component, walk flows F1 to F6 on a single request, and state why the access broker does not sit inside the gateway.

Required reading

  • Logical view: component table, the five design decisions, and flow table F1 to F9. Skim the entity list. Do not redraw the full ER diagram unless you miss a relationship in the retrieval check.
  • The altitude callout at the top of that note. Still no regions, SKUs, or hostnames.
  • Debate 3 in CLAIMS-AND-DEBATES, claim rows only, when you hit the enforcement-point decision.

What to learn

Nobody in the ledger handed over this component cut. The view says so. Treat the boxes as a proposal that realizes C1 to C8, not as a standard architecture.

Memory hook, not the whole table. Group the eleven components by when they work:

When Components Capabilities
Before anyone calls the model AI asset registry, data map and classifier, policy engine, model registry and release pipeline, evaluation and red-team harness C1, C2, C6, C7, C3, C8
On the request Runtime gateway, agent identity and access broker C4
After the request Monitoring and behavior analytics, explainability service, evidence and audit store, incident handler C5, C8, C3

The policy engine also serves release time (C6) and evidence mapping (C8). The incident handler listens to assurance, runtime, and monitoring. One component can realize more than one capability. A capability with no component is a hole. Check C1 through C8 against the table in the view before you leave.

Five decisions are the actual lesson. The tables are the evidence for them.

  1. One choke point, plus a second control that survives it. The runtime gateway sees prompts, outputs, and tool calls. Debate 3 says that is not enough by itself. Flow F4, the access broker, does not depend on the gateway being healthy or honest.
  2. Policy stays outside the model. The engine returns allow, deny, or escalate. The model is not the enforcement point. That matches treating the model as an untrusted user [S7].
  3. Evidence is a flow, not a project. F8 runs from every component into the audit store so C8 falls out of operation.
  4. Retrieval is untrusted. F3 carries text the application did not author. Indirect prompt injection arrives that way [S7].
  5. Component boundaries are unverified against Gartner's layers. Say that if a reviewer asks whether the Market Guide requires this exact cut.

Red links on the runtime diagram: the prompt from the user or agent into the gateway, and the retrieved text from retrieval data into the application. Gray links are not "safe." They are simply not marked as untrusted content. A scoped tool call can still do harm if the scope is wrong. That is F4's job, and it is block 7's topic under excessive agency.

Interaction records store hashes and decisions in the flow description. The entity is still classified sensitive because real prompts may contain personal data. Do not promise the logical view that raw prompts are never kept. The physical view leaves retention UNVERIFIED.

Actions

  1. Pick one story: an employee agent retrieves a policy PDF and files a ticket. Walk F1, F2, F3, F4, F5, F6 in order. Say which step is synchronous.
  2. Mark the two red payloads on that story.
  3. On a scrap diagram, connect AI asset, policy, control, requirement, evaluation result, and evidence item. You need the chain, not every column.
  4. Write the sentence: "If the gateway fails open, the broker still limits tools." Check it against the enforcement-point decision in Logical view.

Retrieval check

Closed book

Which component is the request choke point, and which component must still work if that choke point is bypassed? Why is retrieval marked untrusted? Name the flow that makes compliance a by-product.

Answer

The runtime gateway is the choke point for prompts, outputs, and tool calls. The agent identity and access broker (F4) is separate so least privilege does not depend on the gateway [S7]. Retrieval (F3) is untrusted because indirect prompt injection arrives in external content [S7]. F8, evidence capture, is the by-product flow for C8.

Exit criteria

  • Each of C1 to C8 in Conceptual view points at a component in Logical view.
  • F1 to F9 can be named, and F3 plus the inbound prompt are marked untrusted.
  • Policy-outside-the-model and broker-independence are stated as decisions, not as product features.
  • No hostname, region, or SKU entered the drawing.
