Block 5: Integration and AI elements

Block 5 study guide: integration themes, agent identity, and control points CP1 to CP8.

Time: 60 minutes

Business Explanation

Business Explanation

The platform does not sit alone. Models are often someone else's API, documents come from stores the model did not write, and incidents have to land in the tools security already uses. This hour inventories those neighbors by job, then walks the path from training data to a monitored answer so a reviewer can point at the control that stops oversharing.

Goal

Group the external inventory by theme, state the agent identity rules, and walk control points CP1 to CP8 on one request without naming a recommended product.

Required reading

  • Integration and AI: the inventory table, the identity section, the AI elements table, and the data-path diagram.
  • Do not memorize vendor spellings. Memorize the category and whether the pack read that vendor's docs (almost always no).
  • Logical view flows F1 to F6 if the control-point numbers feel unmoored. CP3 to CP6 are that runtime path.

What to learn

The inventory is a category list with examples, not a shortlist. A name appears only where a ledger source already used it. Zscaler is a vendor explainer for pillars and layers [S9]. Darktrace is the employer of a talk speaker [S12]. AWS appears in a community mapping [S10]. IBM appears as an explainer [S8]. Radware and BigID were search results, not ledger sources. Gov-cloud support is UNVERIFIED on every row because no government-cloud product page was read. Direction matters more than logo: models are bidirectional, SIEM and ITSM are outbound, retrieval content is inbound and untrusted, auditors receive evidence out of band.

Themes to be able to recite:

  1. Model supply (hosted model APIs, registries and MLOps).
  2. Inspection supply (guardrail or AI firewall products).
  3. Identity supply (enterprise identity provider, workload identity).
  4. Data supply (catalog, DLP, vector stores).
  5. Operations sink (SIEM and SOAR, ITSM).
  6. Assurance supply (red-team and evaluation tools).
  7. Accountability sink (auditor or regulator portals).

Identity is architecture, not a checkbox [S12] [S7]:

  • Each agent has its own identity. A shared service account hides who acted.
  • Least privilege and just-in-time scope. Extended functions belong in code, not in a broadly privileged model [S7].
  • A person approves high-risk actions [S7].
  • People who edit policy and evidence should not be the same people who publish models. That separation is a proposal. Mark it as one.

The AI features in scope are an LLM application, retrieval-augmented generation, an agent that calls tools, a classical model that scores or classifies, and a third-party hosted model [S7] [S9] [S12]. Classical models still need drift, bias, and explainability. Do not let the hour collapse into chat bots only.

Control points are where C1 to C8 attach to the path. Learn the number and the question it asks:

CP Question Typical capability
CP1 Is training or fine-tune data labeled and mapped? C2, C7
CP2 Did this version pass evaluation before release? C3, C6
CP3 Was the prompt inspected? C4
CP4 Was retrieval allowed, and is that content treated as untrusted? C4, C7
CP5 Is the tool call scoped to this agent? C4
CP6 Was the output inspected before the user saw it? C4, C7
CP7 Was the interaction logged? C8, C5
CP8 Is someone watching drift and behavior? C5

Red on that diagram: CP3 and CP4. Oversharing is stopped by the combination of CP1 (do not train on what you cannot label), CP6 (do not emit it), and CP5 (do not let a tool read it), under C7. A line in the system prompt is not that control. OWASP notes that system-prompt restrictions can be bypassed [S7].

APIs in the view are patterns: model API, policy query, registry, evidence export. Rate limits are UNVERIFIED except for the warning that unbounded consumption is LLM10 [S7]. Do not invent quotas.

Actions

  1. Fold the inventory into the seven themes above. One example name per theme is enough, tagged "not a recommendation."
  2. Trace one RAG-plus-tool request across CP3, CP4, CP5, CP6, and CP7. Name the logical flow beside each control point.
  3. Write the oversharing sentence: which capabilities and control points, and why a system prompt is not sufficient [S7].
  4. Confirm every gov-cloud cell you might have been tempted to fill still says UNVERIFIED.

Retrieval check

Closed book

Name CP1 to CP8 in order. Which two are the red untrusted points? What is the identity rule for an agent, and what do you know about government-cloud support?

Answer

CP1 label and map training data, CP2 evaluate before release, CP3 inspect input, CP4 check retrieval and treat it as untrusted, CP5 scope the tool call, CP6 inspect output, CP7 log the interaction, CP8 monitor drift and behavior. Red points are CP3 and CP4 [S7]. Each agent gets its own identity and least privilege, not a shared service account [S12] [S7]. Government-cloud support is UNVERIFIED on every inventory row.

Exit criteria

  • Inventory themes match Integration and AI, with vendors demoted to examples.
  • CP1 to CP8 drawn, and the oversharing stop tied to C7 rather than to one product.
  • Agent identity rules stated with [S7] or [S12].
  • No gov-cloud cell upgraded from UNVERIFIED.
