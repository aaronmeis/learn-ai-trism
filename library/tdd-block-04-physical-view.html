Block 4: Physical view

Block 4 study guide: five deployment zones, honest gaps, and the standards profile.

Time: 60 minutes

Business Explanation

Business Explanation

A logical box still has to live somewhere, next to someone else's network. This hour places each proposed part in a zone and names the standards a reviewer can actually cite. It deliberately does not name a product SKU or a government region. Filling those cells from memory would be a false design.

Goal

Place every logical component in one of five zones, name the two red cross-boundary links, and sort the standards profile into voluntary guidance, certification route, and law.

Required reading

  • Physical view: the logical-to-physical table, the zone diagram, the standards table, and the cloud-variant table.
  • Keep Logical view open only as the list of components you must place.
  • desk-research-pass-2026-11-09 only if the view's "article text not read" line confuses you. The desk pass later read EUR-Lex metadata and the application timing [S6]. The view was not rewritten. Do not invent article-by-article obligations.

What to learn

Physical altitude is where it runs. In a normal product pack that means services and SKUs. This pack refused a single cloud, and no vendor page was read for licenses. The honest physical view is zones and patterns. UNVERIFIED in the license, region, and government-cloud columns is the correct content.

Five trust boundaries. Memorize the zone job, not every icon:

Boundary Zone What must live here Why the split exists
TB1 Build Model registry, release pipeline, evaluation and red-team harness Tests and releases are not production traffic
TB2 Runtime Gateway, model serving and applications, agent identity broker, explainability This is where untrusted input arrives
TB3 Observability and security Monitoring, incident handler Detection is not the same team as the model release
TB4 Governance Asset registry, data map, policy engine, evidence store Policy and evidence outlive one application team
TB5 External Users and client agents, third-party model providers, enterprise retrieval stores Outside the platform boundary

The policy engine sits in governance and is called from the runtime zone. Do not move it into TB2 just because the gateway queries it. The evidence store stays in governance even though the gateway writes to it.

Red links, matching the diagram's link styles: client prompts into the gateway, and serving's retrieval from enterprise data. Model calls to a third-party provider are a supply-chain risk [S7] but they are not the two links the figure paints red. Say that distinction out loud so you do not "remember" every external arrow as red.

Standards to be able to sort without the table in front of you:

  • Voluntary risk vocabulary: NIST AI RMF 1.0, functions Govern, Map, Measure, Manage [S2]. NIST AI 600-1 is the voluntary generative profile [S3]. Neither is a NIST certification.
  • Certification route: ISO/IEC 42001:2023, through independent certification bodies. ISO does not itself certify [S5] [S14] [S15].
  • Law where it applies: Regulation (EU) 2024/1689 [S6]. General application 2 August 2026. Do not recite articles you have not read.
  • Threat vocabulary, optional: OWASP Top 10 for LLM Applications 2025 [S7].
  • Mapping aid, optional: the NIST to ISO/IEC 42001 crosswalk [S4].

Customer-managed keys for the evidence store are a recommendation. The only cloud illustration in the ledger is an AWS community mapping [S10]. That does not select AWS.

Commercial, GCC, GCC High, and DoD rows are not researched. The right written answer is UNVERIFIED, not a guess from another project.

Actions

  1. List the eleven logical components down the page. Write a zone next to each. Check against the mapping table in Physical view.
  2. Draw TB1 to TB5 as five labeled bands. Add only the two red links, labeled with their payload.
  3. Write a four-row standards card: voluntary, certifiable, law, optional threat list. One [S#] per row.
  4. Leave license, region, retention, and government-cloud blank on purpose. Write UNVERIFIED so a later reader does not "helpfully" fill them.

Retrieval check

Closed book

Where do the gateway, the policy engine, and the evaluation harness run? Which two links are red? What do you write in a SKU cell in this pack, and why?

Answer

Gateway in the runtime zone (TB2). Policy engine in the governance zone (TB4), called from runtime. Evaluation harness in the build zone (TB1). Red links are untrusted prompts into the gateway and retrieval from enterprise data. SKU cells say UNVERIFIED because the pack is vendor-neutral and no license page was read.

Exit criteria

  • Every component from Logical view maps to a zone in Physical view or is explicitly UNVERIFIED.
  • TB1 to TB5 named, with the two red payloads correct.
  • NIST, ISO/IEC 42001, the EU AI Act, and OWASP sorted by the kind of authority they have.
  • No government-cloud cell filled from memory.
