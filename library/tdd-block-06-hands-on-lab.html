TDD day blocks

Block 6: Hands-on lab

Block 6 desk-only lab: walk the proposed build order and one public source. No installs.

Time: 60 minutes

Business Explanation

Business Explanation

There is no product to click. The useful hands-on work is to sequence the build so evidence and inventory exist before anyone blocks traffic, and to read one primary page so the design review cites a document instead of a memory. Installing a guardrail to "see what happens" is a different project and is out of bounds today.

Goal

Restate the ten-step build order from the detailed design, say which dependency each early step satisfies, and capture one sentence from a public ledger page. Do not install anything. Do not run E3W.

Required reading

  • Detailed design, especially the startup table and the UNVERIFIED open items.
  • One public page from source-ledger, chosen in the actions. Preferred: NIST AI RMF publication page [S2] or the OWASP LLM01:2025 entry [S7b].
  • desk-research-pass-2026-11-09 section E3W, only to confirm the lab compare stays unrun.

What to learn

Detailed design normally names packages, paths, and commands. This pack has none. AI TRiSM is not a product, the reference is vendor-neutral, and lab access is docs and desk. The view therefore offers a proposed order. Every row is a proposal. The diagram file 05-detailed-design.drawio was not authored, on purpose, until a realization is chosen.

The order is dependency order, not a project plan with dates:

Step What stands up Dependency it satisfies
1 Evidence and audit store Later controls have somewhere tamper-evident to write. Retention is UNVERIFIED.
2 AI asset registry, then discovery You cannot govern systems you have not listed. Catalog-first matches the secondary feature list [S8].
3 Data map and classifier Assets gain datasets and labels [S8].
4 Policy engine, small starter set Decisions need rules grounded in NIST Govern and the organization's risk tolerance [S2].
5 Agent identity broker Agents get identities before they get tools [S12].
6 Runtime gateway in monitor-only Learn real traffic before you block it. Monitor-only is a proposal.
7 Evaluation harness on the release pipeline No version goes live without results. Red teaming first matches the academic talk [S11].
8 Monitoring, then incident hand-off into existing SOC tools Drift and behavior alerts need a case path [S9].
9 Enforce mode, per use case Fail-closed or fail-open is a decision, not a default. Latency and false positives are UNVERIFIED until E3W or a real pilot.
10 First evidence pack using the NIST to ISO/IEC 42001 crosswalk C8 is exercised, not slides [S4].

Why evidence before the catalog: a discovery scan that is not recorded cannot be shown later. Why catalog before policy: a policy with no asset scope is a slogan. Why monitor-only before enforce: you do not yet know the false-positive cost. Why step 9 is not "turn it all on": Debate 3 says a gateway that fails, or fails open, must not be the only control. The broker from step 5 is already in place.

Interfaces you may describe and must not pretend to have run: gateway policy query (logical flow F2), asset registration (F7), evidence export (F8), evaluation run. There is no CLI in this pack.

Desk trace, not a lab: open exactly one URL. Copy one sentence into NOTES with the [S#], the title, and the date you opened it. If the page disagrees with a view line, write the disagreement. Do not silently "fix" the view in your head. Known tension: Physical view still says some primary pages were not read. The desk pass later read [S1], [S5], and [S6]. Prefer the ledger's read status.

Forbidden in this block:

  • Package installs, containers, API keys, tenant changes.
  • E3W, the prompt-injection compare against a guardrail product.
  • Inventing config paths, ports, or SKUs to make the detailed design "look finished."
  • Drawing assets/diagrams/05-detailed-design.drawio from imagination.

Actions

  1. Write the ten steps in your own words. Next to steps 1, 2, 6, and 9, write the dependency sentence from the table above.
  2. Open one allowed URL. Record one sentence, the [S#], and whether it supports catalog-first, red-team-first, or least privilege.
  3. List the five open items from Detailed design as questions you would ask a sponsor. Do not answer them with guesses.
  4. In Progress Log, leave the block 6 day checkbox for yourself. Do not mark E3W run anywhere.

Retrieval check

Closed book

Why does the evidence store come before the catalog, and why is the gateway monitor-only before it enforces? Which test is still unrun, and what would you need before running it?

Answer

The store comes first so later registrations and decisions have a tamper-evident record. The catalog comes before enforcement so policy has an asset to apply to [S8]. Monitor-only gathers real traffic before blocking. Enforce-mode latency and false positives are UNVERIFIED. E3W, the guardrail comparison, is unrun until an explicit install GO. See Detailed design.

Exit criteria

  • Ten-step order restated from Detailed design, including monitor-only before enforce.
  • One public ledger page traced, with a quoted sentence and [S#] in your notes.
  • No install, no tenant change, no invented CLI.
  • E3W still recorded as unrun. Open items left open.
