Block 3: Active practice

Block 3 desk exercises: place a use case, OWASP LLM risks, and NIST functions on the AI TRiSM map.

Time: 90 minutes Goal: Produce three desk maps you can defend, each tagged with what was read and what is only a name. Pack: AI-TRISM hub

Business Explanation

Business Explanation

Fluency here means you can place a control without opening a vendor brochure. The three exercises use one internal assistant, the 2025 OWASP LLM list, and NIST's four functions. The keys are study placements, not a Gartner crosswalk.

Sources

  • [S2] NIST functions. [S7] ten risk names. [S7b] LLM01 mitigations, read in full.
  • [S8] [S9] [S11] [S12] for catalog, layers, firewall, and agent identity.
  • TDD logical components and flows: logical view. Integration risks: integration view.
  • Do not open the folded keys until your table exists on paper.

Setup

Use case for all three exercises. Call it Handbook Assistant.

  • Employees ask questions about an approved employee handbook.
  • Retrieval adds handbook passages to the prompt.
  • The assistant may draft an IT ticket through a tool. It may not change payroll.
  • Users and documents stay inside one company. EU tier is unclassified until Annex III is read [S6].
  • Actors, from the TDD conceptual view: application owner, AI risk owner, security operations, privacy officer, end user, the agent, and an auditor.

Write maps by hand or in a note titled Handbook Assistant maps. Time boxes below include checking.

Exercise A. Four layers, 25 minutes

Place Handbook Assistant on the four secondary layers [S9]. For each layer name one control, the actor who owns it, and the source grade of the layer name.

After your attempt, check:

Study key A

AI governance. Register the assistant, the model version, and the ticket tool in the catalog. Name an application owner and a risk tier. Owner: AI risk owner. Layer name is secondary [S8] [S9]. AI runtime inspection and enforcement. Gateway checks the user prompt, the retrieved passage, the draft answer, and the ticket tool call. Owner: security operations with the application owner. Bo Li's outer firewall is the pattern [S11]. Layer name is secondary. Information governance. Label handbook documents. Treat retrieved text as untrusted external content. Keep ticket text from carrying data the handbook is not allowed to reveal. Owner: privacy officer. Matches IBM's data-protection category [S8] and LLM01 mitigation 6 [S7b]. Infrastructure and stack. The ticket tool runs as its own agent identity with permission to draft a ticket and no permission to payroll. Quotas cap model calls. Owner: platform team. Identity demand is from [S12], with vendor interest noted. Least privilege is LLM01 mitigation 4 [S7b].

Exercise B. OWASP LLM01 to LLM10, 35 minutes

Rows are the 2025 names [S7]. Columns: layer you would touch first, second layer if needed, mitigation text read or not.

Only LLM01 has a full mitigation page in this pack. LLM02 is an excerpt in the TDD integration view: sanitize before training, and system-prompt restrictions can be bypassed. LLM03 through LLM09 are names. LLM10 is a name, with quotas discussed as a blast-radius control. Do not invent official mitigations for the unread entries.

After your attempt, check:

Study key B

LLM01 Prompt Injection. Runtime first, information second. Mitigations read [S7b]. Retrieved handbook text is the indirect path. LLM02 Sensitive Information Disclosure. Information governance first, runtime output check second. Excerpt only. LLM03 Supply Chain. Infrastructure first, governance second for vendor acceptance. Name only. LLM04 Data and Model Poisoning. Information governance for training and fine-tune data. Name only. Handbook Assistant is mostly retrieval, so say whether you even fine-tune. LLM05 Improper Output Handling. Runtime output check, then infrastructure on the ticket tool that consumes the output. Name only. LLM06 Excessive Agency. Infrastructure identity and least privilege, plus governance for human approval if the tool ever posts the ticket. Name only. The analogy to LLM01 mitigations 4 and 5 is the pack's, and the claims note says so. LLM07 System Prompt Leakage. Runtime output inspection. Name only. LLM08 Vector and Embedding Weaknesses. Information governance on the retrieval store, infrastructure on who can write embeddings. Name only. LLM09 Misinformation. Runtime plus the Measure function's evaluation harness. Name only. Do not call this a fairness control. LLM10 Unbounded Consumption. Infrastructure quotas on the model API and the gateway. Name only. Any row you marked "official OWASP says" for LLM03 to LLM10 is wrong for this pack.

Exercise C. NIST functions to controls, 25 minutes

Map Govern, Map, Measure, and Manage onto control owners for Handbook Assistant. Use TDD logical components if you want names. Label the component split as a proposal. The functions themselves are [S2].

After your attempt, check:

Study key C

Govern. Policy engine, named risk owner, catalog ownership, evidence of approvals. This is where ISO/IEC 42001 accountability will later ask for records [S14]. Map. Asset record plus data map: which handbook corpus, which ticket fields, which users. Context before metrics [S2] [S8]. Measure. Evaluation harness on answer faithfulness to the handbook, red team for prompt injection [S11], monitoring for drift in refusal behavior. Explainability notes for a sample of answers. AI 600-1 tables are not the source of specific tests yet [S3]. Manage. Release gate before a new model version, incident path when the gateway blocks a burst of injection attempts, retirement of an old index. Human approval before the agent posts a ticket, if posting is even allowed [S7b]. A function with no owner is an incomplete map. A component presented as a Gartner product name is a failed map.

Actions

  1. Write Exercise A before you expand key A.
  2. Write Exercise B. Add a column Read? and force yourself to type name only nine times if that is the truth.
  3. Write Exercise C in four rows. Under the table, one sentence on what is proposal versus what is NIST.
  4. Star the two cells you would be weakest defending. Those go to the Missed-it cell in Progress Log during block 6.

Retrieval check

For Handbook Assistant, which layer owns the ticket tool's privilege, and which source is primary for that control idea?
Answer

Infrastructure and stack, as a secondary layer name. The control idea is least privilege from OWASP LLM01 [S7b], reinforced by the CSA talk on agent identity [S12]. The layer name is not from the Gartner press release.

How many OWASP 2025 entries have full mitigation text in this pack?
Answer

One. LLM01 [S7b]. The other nine are names from the list page [S7], with a short excerpt on LLM02 in the TDD integration view.

Which NIST function owns a pre-release red team, and is the harness a NIST component?
Answer

Measure owns the testing. Manage owns the release decision that uses the result. The harness is a TDD proposal that realizes that function, not a box drawn in AI RMF [S2] [S11].

Exit criteria

  • Three maps exist, written before the keys were opened.
  • Every layer name on your page is tagged secondary.
  • Unread OWASP entries are marked name only.
  • NIST functions are not relabeled as TRiSM pillars.
