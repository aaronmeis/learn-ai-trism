Altitude rule

Detailed design means exactly how it is built. Name packages, config paths, CLI commands, interfaces, and startup order. Mark every unconfirmed item UNVERIFIED. No "Claude" in labels. Use "Coding agent" / "Agent CLI" or named non-banned tools.

Draft status: no product is being built

AI TRiSM is a framework, not a product. The pack is vendor-neutral and has docs-and-desk lab access only, so there are no packages, config paths or commands to document. This view therefore gives a proposed build order for a reference implementation, derived from the logical view. Every row is a proposal. Nothing here was run or checked against product documentation.

Startup / boot order

Proposed order for standing up a reference implementation. The order follows dependencies in the logical view: you cannot enforce policy on assets you have not listed, or prove controls without an evidence store.

Step What runs Config / path Source
1 Evidence and audit store Append-only store, retention set from the strictest requirement. UNVERIFIED which. Proposal
2 AI asset registry, then discovery of existing AI use Registry plus scans. Catalog first, as in Gartner's feature list as IBM reports it [S8] [S8]
3 Data map and classifier Link assets to datasets and labels [S8]

5 Identity and access broker for agents Per-agent identity, scoped tokens [S12]
6 Runtime gateway in monitor-only mode Log without blocking to learn real traffic Proposal
