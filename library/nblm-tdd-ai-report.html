1.2 End-to-End AI Data Path and Control Points (CP1–CP8)

The enterprise AI data path proceeds chronologically through eight mandatory Control Points (CP1 through CP8) across model creation, runtime execution, and out-of-band monitoring:

  1. CP1 (Data Labeling & Mapping): Governs training and fine-tuning data prior to model creation by classifying data sensitivity, establishing provenance, and mapping data lineage.
  2. CP2 (Pre-Release Evaluation): Gates approved releases post-model creation by subjecting candidate model versions to automated evaluation and red-teaming test suites for accuracy, bias, and attack resistance.
  3. CP3 (Input Inspection): Evaluates user and agent prompts inline at the runtime gateway to inspect and filter injection attacks, malicious payloads, and unauthorized data prior to application execution.
  4. CP4 (Retrieval & Untrusted Content Handling): Applies access checks, content security labeling, and sanitization to documents and embeddings retrieved from enterprise data stores. CP4 explicitly mitigates indirect prompt injection—wherein untrusted external content or embedded payloads attempt to hijack the model's execution context—before merging retrieved data into the model prompt.
  5. CP5 (Scoped Tool Calls): Enforces identity broker constraints, just-in-time token scoping, and strict least privilege on actions attempted by AI agents against external tools and APIs. Grounded in defense-in-depth principles, CP5 relies on a dedicated Agent Identity and Access Broker rather than trusting runtime gateway proxy inspection alone, ensuring that compromised prompts cannot execute unauthorized tool actions.
  6. CP6 (Output Inspection): Validates draft outputs inline at the runtime gateway prior to user delivery to detect and block sensitive information disclosure, unapproved content emission, and formatted response policy breaches.
  7. CP7 (Interaction Logging): Captures complete prompt and response interaction records asynchronously, emitting telemetry and cryptographic hashes to logging pipelines without adding inline execution latency.
  8. CP8 (Drift & Behavior Monitoring): Performs continuous out-of-band observability analytics on logged interaction records to detect performance degradation, concept drift, demographic bias, and anomalous agent behaviors in production.

3. AI TRiSM Integration Surface & External System Topology

3.1 Agent Identity and Access Governance Surface

Autonomous AI agents present unique threat vectors requiring explicit identity boundary enforcement. Enterprise security architectures must enforce the following controls across the agent integration surface:

  • Dedicated Agent Workload Identities: Every autonomous agent must be assigned an individual, non-shared workload identity. Shared service accounts are strictly prohibited. Identity configurations must answer: "Who is the agent, and what specific assets can it access?" [S12]
  • Just-In-Time (JIT) Scoped Tokens: Execution credentials issued to agents must be ephemeral, tightly constrained to the specific task execution window, and minted exclusively via a dedicated Agent Identity and Access Broker.
  • Deterministic Application Boundary & Least Privilege: Agent authorization must adhere to strict least privilege. Crucially, architects must encapsulate complex extended functions within deterministic, governed application code rather than delegating state changes natively to non-deterministic model capabilities [S7].
  • Human-in-the-Loop Approvals: High-risk actions (e.g., financial transactions, database writes, system state modifications) require mandatory, out-of-band human confirmation prior to execution [S7].
  • Missing Integration Specifications: The source context explicitly documents a significant integration gap: there are no technical specifications defining how enterprise Identity Providers (IdPs) federate identity claims with third-party AI model providers.
