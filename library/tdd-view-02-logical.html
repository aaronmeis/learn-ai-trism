Logical View — AI-TRISM

Logical view of AI-TRISM: components, data entities, and flows, still vendor-neutral.

Pack: 00 - AI-TRISM Hub · Block: Block 3 · Prev: Conceptual · Next: Physical

Altitude rule

Logical means which parts and how they talk, independent of where they run. Components have responsibilities and interfaces. Data entities have attributes and relationships. Still no regions, SKUs, or hostnames.

Draft status

This is the agent's proposed decomposition of capabilities C1 to C8 into components. No source in the ledger prescribes it. Components are marked as proposal throughout. Threat names come from the OWASP 2025 list page [S7].

Design decisions at this level

  • Enforcement point. The runtime gateway is a single logical choke point for prompts, outputs and tool calls. Debate 3 in CLAIMS-AND-DEBATES questions whether this is enough on its own, so the access broker (F4) is a separate component and does not depend on the gateway working.
  • Policy outside the model. The policy engine decides, and the model is never trusted to enforce policy on itself. This follows the idea of treating the model as an untrusted user [S7].
  • Evidence as a first-class flow. F8 exists so that compliance mapping (C8) is a by-product of operation rather than a separate project.
  • Retrieval data is untrusted. F3 is marked untrusted because indirect prompt injection arrives through external content [S7].
  • UNVERIFIED: whether Gartner's layers imply these exact component boundaries. The decomposition is a proposal.
