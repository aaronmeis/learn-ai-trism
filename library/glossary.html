Glossary: AI-TRISM

Business Explanation

Business Explanation

Reviewers talk past each other when "layer," "pillar," "control," and "guardrail" mean different things. This list fixes those words for the pack. If a term is a vendor's account of an analyst guide, the definition says so.

Term Definition View Block
AI TRiSM Gartner's name for technical capabilities that support trust, risk, and security of AI. A market category, not a certification scheme [S1] [S8]. Conceptual 1, 2
Four layers (secondary) Placement structure secondary sources attribute to a Gartner Market Guide: AI governance, runtime inspection and enforcement, information governance, infrastructure and stack [S9]. [S1] says "four layers" and does not name them. Conceptual 1, 2
Four pillars (secondary) Crosswalk in vendor explainers: explainability and model monitoring, ModelOps, AI application security, and privacy [S9] [S10]. Not read from a Gartner-owned pillar list. Conceptual 1, 2
C1 to C4 Catalog, AI data mapping, continuous assurance, and runtime inspection and enforcement. IBM's account of Gartner guidance [S8]. Conceptual 2
C5 to C8 Explainability and monitoring, ModelOps lifecycle, information and privacy governance, and compliance evidence. Derived in this pack from pillars and NIST [S9] [S2] [S4]. Conceptual 2
AI asset Any model, application, agent, or dataset under governance. Conceptual, Logical 2, 3
Trustworthiness characteristic One of seven NIST properties, including safe and fair with harmful bias managed [S2]. Those two lack a clearly named pillar here. Conceptual 2
Policy A rule the organization wants enforced. Distinct from the component that decides it. Conceptual, Logical 2, 3
Control A mechanism that implements a policy. Not the same noun as the policy. Conceptual, Logical 2, 3
Evidence item A record that a control ran and what it found. Target of flow F8. Logical 3
Agency How far an AI system can act through tools [S7]. Drives least privilege, not only text filters. Conceptual, Integration 2, 5
Runtime gateway Logical choke point for prompts, outputs, and tool calls. Realizes C4. Not sufficient alone. Logical, Physical 3, 4
Policy engine Decides allow, deny, or escalate outside the model [S7]. Lives in the governance zone. Logical, Physical 3, 4
Agent identity and access broker Gives each agent an identity and a scoped credential. Flow F4. Must not depend on the gateway. Logical, Integration 3, 5
Untrusted flow A link that carries content the organization did not author. Here: user prompts, and retrieved text [S7]. Drawn red. Logical, Physical 3, 4
TB1 build zone Registry, release pipeline, and evaluation harness. Not production traffic. Physical 4
TB2 runtime zone Gateway, model serving, agent identity broker, explainability. Where untrusted input arrives. Physical 4
TB4 governance zone Asset registry, data map, policy engine, evidence store. Physical 4
TB5 external Users, client agents, third-party model providers, and enterprise retrieval stores. Physical, Integration 4, 5
Control point (CP1 to CP8) Numbered place on the AI data path where a capability attaches, from labeling training data through behavior monitoring. Integration 5
Monitor-only mode Gateway logs without blocking so real traffic is understood before enforce mode. A proposal in the build order. Detailed design 6
ISO/IEC 42001 AI management-system standard. Certifiable by independent bodies. ISO does not itself certify [S14] [S15]. Physical 4, 8
NIST AI RMF Voluntary framework. Functions Govern, Map, Measure, Manage [S2]. AI 600-1 is the voluntary generative profile [S3]. Physical, Conceptual 1, 4
OWASP LLM Top 10 (2025) Community threat names for LLM applications [S7]. Full mitigation text in this pack is limited to LLM01 [S7b]. Integration 7
Honest UNVERIFIED A cell left empty because the source was not read. Required for SKUs, regions, and gov-cloud in this pack. Physical, Detailed design 4, 6
EA framework crosswalk Architect overlay that places pack elements into TOGAF ADM, DoDAF viewpoints, and UAF 1.3 grid cells. Separate from the NIST-to-ISO control crosswalk [S4]. See ea-framework-crosswalk. All views 2, 8
UAF 1.3 OMG Unified Architecture Framework. Grid is domains × aspects (e.g. Op-Sr = Operational Structure). Architecture literacy for this pack [S17]. AI-TRISM sources do not prescribe UAF placements. Conceptual → Detailed design 2, 8
UAF domain-aspect cell A filled grid cell such as Sm-Ov, St-Tx, Op-Cn, Sv-Sr, Rs-Cn, Sc-Sr, Sd-Tx, Pj-Rm, Ar-Sr. Teach the pair, not a DoDAF OV number under a UAF label [S17]. All views 2, 8
DoDAF (kept alongside UAF) Department of Defense Architecture Framework viewpoints (OV/SV/DIV/StdV) still used in briefs. OUSD(R&E) points toward UAF superseding DoDAF over time; no CIO retirement found in the pack's UAF brief [S18]. All views 2, 8
TOGAF ADM Open Group Architecture Development Method phases A–F used in each view's Framework lens. All views 2, 8
