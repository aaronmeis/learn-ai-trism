Block 7: Failure modes and security

Block 7 study guide: OWASP LLM risks and talk limits, mapped to flows and control points.

Time: 45 minutes

Business Explanation

Business Explanation

A control plane that only looks complete will still fail in specific, nameable ways. This block puts those names on the diagrams from earlier in the day: which flow carries the attack, which control point is supposed to catch it, and which mitigations this pack has actually read. The point is to stop a design review from accepting "we have a guardrail" as a full answer.

Goal

Place the OWASP 2025 risk names and the two talk warnings onto a flow or a control point. Keep unread mitigation text unread.

Required reading

  • Integration risks table in Integration and AI.
  • Red flows and the "policy outside the model" decision in Logical view.
  • Debate 3 in CLAIMS-AND-DEBATES, including the E3A count.
  • Do not open vendor white papers to fill UNVERIFIED cells.

What to learn

OWASP's 2025 list is a threat vocabulary, not a control framework [S7]. The pack read the ten names. It read the full LLM01 page [S7b]. LLM02 is an excerpt. LLM03 through LLM09 were not read as entries. LLM10 is the name plus a consumption warning. If you write a mitigation for an unread entry, you are inventing.

Use this placement. The "read status" column is part of the answer.

The teaching point from E3A is the weight, not a slogan. Runtime inspection (C4, the gateway, CP3 and CP6) is the right place for the filtering items. It is the wrong place to stop. Privilege (CP5, the broker), human approval, and content segregation are the rest of LLM01 [S7b]. That is why block 3 refused to hide the broker inside the gateway.

Do not write attack procedures, payloads, or bypass steps. Naming the risk and the control point is the whole assignment.

Actions

  1. On a copy of the runtime path, tag LLM01, LLM02, LLM06, and LLM10 onto flows or control points. Four tags are enough.
  2. Write two sentences you would say if a sponsor says "the firewall covers prompt injection." Use [S7b], [S11], and [S12]. Include the vendor-interest caveat on [S12].
  3. Star every row whose mitigation you have not read. Those stars are exit criteria, not shame.
  4. Add one non-OWASP failure: evidence added after go-live, which skips F8. The fix is step 1 of the build order in Detailed design.

Retrieval check

Closed book

Why are runtime guardrails necessary and not sufficient? Where does indirect prompt injection enter? What will you refuse to invent for LLM03?

Answer

Guardrails are necessary because the model is not fully fixable, so an outer inspection layer is a real proposal [S11], and LLM01 includes filtering [S7b]. They are not sufficient because most of the LLM01 mitigations are privilege, architecture, or process, and a talked-through limit is that filters cannot judge every input, output, and agent identity [S7b] [S12]. Indirect prompt injection enters on retrieval, flow F3 and control point CP4 [S7]. For LLM03 you will name supply chain and the third-party boundary, and you will not invent the unread mitigation text.

Exit criteria

  • A failure table covers prompt injection, sensitive disclosure, excessive agency, supply chain, and unbounded consumption, each tied to Logical view or Integration and AI.
  • LLM01's mix of filtering versus privilege is stated from [S7b].
  • Both talks cited, with vendor interest on [S12], and E3W left unrun.
  • Unread OWASP entries stay name-only.
