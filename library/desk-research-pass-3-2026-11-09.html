Five foundational pillars (Ray synthesis)

Ray unites five pillars (not the four-pillar vendor set in [S9]/[S10]):

  1. Explainability with real-time drift monitoring — SHAP, LIME, saliency; PSI / KS / JS drift; CI/CD XAI gates
  2. ModelOps governance — versioning (Git/DVC), containers, IaC, canary/blue-green, policy-as-code (OPA), retirement/registry
  3. AI application security — prompt injection and poisoning defenses, SAST/DAST/SCA, API gateway auth/rate limits/ABAC, RASP, red team
  4. Data protection and privacy — minimization, k-anonymity / DP, federated learning, SMPC/HE, consent, lineage
  5. Adversarial resilience — FGSM/PGD adversarial training, distillation, ensembling, feature squeezing, runtime detectors

Debate 1 implication: Ray is a scholarly synthesis, not a Gartner primary. It expands the secondary pillar set by adding adversarial resilience as a first-class pillar. Pack still prefers Gartner layers for architecture placement; Ray’s five pillars are useful as a control checklist that names fairness-adjacent work under trust taxonomy and hardens AppSec with an explicit adversarial pillar.

Related-work note inside Ray: IBM/Gomstyn–Jonker are cited for a different five-item list (governance, trustworthiness, fairness, reliability, data protection). Do not conflate that IBM framing with Ray’s five technical pillars above.

Three aligned taxonomies (Section IV)

Taxonomy Dimensions / categories (as named in Ray)
Trust Fairness, explainability, transparency, accountability, ethical alignment, inclusiveness, human oversight, trust calibration, sustainability
Risk Model, data, legal, operational, reputational, ethical, societal, cognitive, emergent, third-party (abstract also lists legal/operational/societal/cognitive/emergent/third-party)
Security controls Access management, infrastructure hardening, runtime enforcement, privacy-enhancing techniques (plus AppSec practices surveyed in §III)

Trust taxonomy names fairness explicitly. That strengthens Debate 4 room language: scholarly TRiSM synthesis treats fairness as a trust dimension even when vendor pillar titles omit it.

Toxicity taxonomy (Section V) — generative AI

Hate/harassment, violent content, self-harm, sexual content, illicit behavior, extremist content, advice misuse, personal data leakage, mis/disinformation, bias-oriented discrimination, profanity/obscenity, jailbreak/prompt-engineering attacks, multimodal toxicity, model-amplified dataset-driven toxicity — each mapped to TRiSM safeguards in the paper.

Adoption challenges (Section VII) — architect-relevant

Fragmented tooling; late integration into the lifecycle; ethical gaps; weak algorithmic transparency; hosted-LLM handling; human skill erosion; evolving threat landscape; cross-functional coordination; scalability; lifecycle governance controls; dynamic regulatory compliance; insufficient stakeholder understanding.

Future roadmap (Section VIII) — headline items

Adaptive AI-driven policy engines; causal explainability; privacy-by-design pipelines; continuous real-time assurance; federated governance; quantum-safe architectures; sustainable “green AI.”
