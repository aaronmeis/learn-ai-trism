Block 7: Application

Block 7: design and defend a vendor-neutral AI TRiSM one-pager.

Time: 60 minutes Goal: Design and defend a vendor-neutral one-page reference architecture for a named system. Pack: AI-TRISM hub

Business Explanation

Business Explanation

The one-pager is what the design review keeps. It shows where trust, risk, and security controls sit, which standard or law each control answers to, and which kind of tool does the work. Product names are optional. The defense is not.

Actions

  1. 5 minutes. Pick the system. Default is Handbook Assistant from block 3. You may swap in another internal assistant if you can describe it in four lines. Stay desk-only.
  2. 30 minutes. Fill the one-pager outline below. One page. If it spills, cut SKUs and adjectives first.
  3. 10 minutes. Mark every layer name secondary. Mark every component "proposal" unless a ledger source requires that control.
  4. 10 minutes. Speak the 90-second defense. Then answer one hostile question from block 4 without notes.
  5. 5 minutes. File the page under this block or in your daily note. Point the Progress Log application row at it when you study.

One-pager outline

Use these headings. The sample under each heading is Handbook Assistant. Replace the sample if you changed the system. Keep the headings.

1. System

Handbook Assistant answers employee questions from an approved handbook corpus and may draft an IT ticket. It may not change payroll, benefits, or disciplinary records. EU risk tier: unclassified in this pack until the relevant annex is read [S6].

2. Authorities on one line each

Authority This design uses it for
AI TRiSM, market [S1] Placement of controls. Layer count is primary. Layer names are secondary [S9].
NIST AI RMF [S2] Govern, Map, Measure, Manage. Seven characteristics as the trust test.
NIST AI 600-1 [S3] GenAI profile acknowledged. Specific risk rows not yet assigned.
ISO/IEC 42001 [S5] [S14] AIMS requirements and the evidence a certification body would sample.
Crosswalk [S4] Pointer from an RMF subcategory to a 42001 control. Example recorded in the claims note: Govern 6.1 to B.10.2.
EU AI Act [S6] In scope only if the system is placed on the EU market or used in the EU. Tier not assigned.
OWASP LLM 2025 [S7] Threat names. Full mitigations cited only for LLM01 [S7b].

3. Layers and controls

Layer, name secondary Control on this system NIST function Tool category
AI governance Catalog entry, owner, risk tier, approval to draft tickets Govern AI asset registry, policy engine, evidence store
AI runtime inspection and enforcement Check prompt, retrieved passage, answer, and tool call Manage, with Measure feeding the rules Runtime gateway
Information governance Label the corpus. Treat retrieval as untrusted. Restrict ticket fields Map Data map and classifier
Infrastructure and stack Separate agent identity. Ticket-draft scope only. Call quotas Manage Agent identity broker, model hosting, quotas

Pillar crosswalk, still secondary: explainability sits with sampled answers in Measure. ModelOps sits with the release pipeline in the build zone. Application security sits on the gateway and the broker. Privacy sits on the data map.

Fairness and safety: listed in NIST's seven and in the Gartner outcome list [S1] [S2]. No pillar is named for them. Leave the gap visible. Debate 4 is open.

4. Zones

From the TDD physical view, as a proposal:

Zone What runs there for this system
Build Model registry, release gate, evaluation and red-team harness [S11]
Runtime Gateway, the assistant, the identity broker
Observability Interaction log, drift and abuse alerts, incident handoff
Governance Catalog, data map, policy, evidence store
External Employees, the handbook store, the ticket system, any hosted model

Trust boundary that matters: retrieved handbook text and user prompts enter as untrusted [S7b]. The ticket system is a tool behind the broker, not a place the model authenticates with a shared admin account [S12].

5. Evidence the reviewer can ask for

Ask You show
What systems exist? Catalog row for the assistant, the index, and the ticket tool [S8]
What data do they touch? Data map of the handbook corpus and ticket fields
Does it still behave? Evaluation result before release, plus a red-team note for prompt injection [S11]
What stops a bad action? Gateway decision log and the broker's scope
Can an auditor replay it? Evidence pack: approvals, tests, decisions [S4]
What standard is that? A 42001 clause or control via the crosswalk, not a TRiSM certificate

6. Claims this page does not make

  • Layer names are not quoted as free-page Gartner text.
  • Pillar names are not a Gartner-owned list in this ledger.
  • No TRiSM certification.
  • No Ray 2026 finding [S13].
  • No guardrail detection rate.
  • No gov-cloud SKU. The TDD physical view left that unverified.
  • No EU high-risk determination.

90-second defense

Speak this shape, then use your own system name.

  1. The system does one job, and the job has a hard stop. Handbook Assistant drafts tickets and does not touch payroll.
  2. Requirements sit on ISO/IEC 42001. Risk language sits on NIST's four functions. TRiSM only places the tools. Gartner counts four layers and, on the page we read, does not name them.
  3. Runtime inspection checks prompts, retrieval, answers, and tool calls. A separate identity can draft a ticket and cannot do anything else. Red team comes before we trust the filter.
  4. Evidence is the catalog, the test result, the decision log, and the approval. That is what a certification body can sample. We are not certifying to a market category.
  5. Open items: AI 600-1 risk rows, Debate 4 on fairness and safety, EU annex if this system is in scope, and the unread Market Guide PDF.

Retrieval check

Which three things must appear on the one-pager for the day outcome to count?
Answer

The four layers as a placement map with source grades, the standards anchors with NIST and ISO/IEC 42001 named, and tool categories rather than a mandatory SKU. Risks for the system are mapped, at least LLM01 and excessive agency.

What do you say when a reviewer asks for the product you will buy?
Answer

Name the category and the zone: a runtime gateway in the runtime zone, an identity broker beside it, an evidence store in the governance zone. SKUs are a later selection. Gov-cloud availability is unverified in this pack.

Where does the conformance claim point?
Answer

At the AIMS under ISO/IEC 42001, sampled through the evidence pack and tied to NIST subcategories by the crosswalk [S4] [S14]. TRiSM is the map of where those controls live.

Exit criteria

  • A one-page design exists for a named system.
  • Layers, standards anchors, and tool categories are all on it.
  • The cannot-claim list is on it.
  • You spoke the 90-second defense once.
  • A hostile question from block 4 was answered without opening the ledger.
